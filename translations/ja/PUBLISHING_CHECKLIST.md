# 公開チェックリスト

公開アップデートをコミットまたはプッシュする前にこのチェックリストを使用してください。

## セーフティ

- Markdownファイル、ノートブック、サンプルデータ、スクリプトにAPIキー、トークン、パスワード、またはプライベートエンドポイントが書き込まれていないことを確認してください。
- 資格情報は環境変数またはマネージドIDに保持し、コミットされたファイルには含めないでください。
- `.env`ファイルや実行済みのノートブック出力ファイルをコミットしないでください。
- `.env.example`はプレースホルダーのみにしてください。

## 検証

リポジトリの検証スクリプトを実行してください：

```powershell
python scripts\verify_notebooks.py
```

実装変更を公開する前にローカルで安全にノートブック全体を実行してください：

```powershell
python scripts\verify_notebooks.py --execute
```

期待されるチェック項目：

- ローカルのMarkdownリンクが通ること
- ノートブックJSONの検証が通ること
- ノートブックに保存された出力や実行カウントが含まれていないこと
- 高リスクの秘密パターンスキャンが通ること
- 公開ノートブックがローカルで実行できること
- `drafts/`以下のドラフト資料は意図的にスキップされていること

## レビュー

- READMEの記事リンクが意図したファイルを指していることを確認してください。
- 各記事にリポジトリナビゲーションおよび関連ノートブックリンクがあることを確認してください。
- ドラフトが公開インデックスからリンクされていない、または公開準備ができていることを確認してください。
- GitHubのIssueおよびプルリクエストテンプレートがリポジトリワークフローに適合していることを確認してください。
- 記事の検証結果が最新のノートブック出力と一致していることを確認してください。
- プッシュ後にGitHub Actionsワークフローが期待通りに動作することを確認してください。
- `CHANGELOG.md`が公開するアップデートを反映していることを確認してください。
- `CONTRIBUTING.md`が引き続きリポジトリワークフローに適合していることを確認してください。

## Git

- `git status --short --branch`の内容を確認してください。
- `git diff --stat`の内容を確認してください。
- 明確に準備ができた場合のみコミットおよびプッシュしてください。
