# Чек-листа за објављивање

Користите овај чек-лист пре комитовања или пушовања јавних ажурирања.

## Безбедност

- Потврдите да у Markdown фајловима, нотебуцима, примерима података или скриптама нису записани API кључеви, токени, лозинке или приватне странице.
- Чувајте акредитиве у променљивим окружења или управљаном идентитету, а не у комитованим фајловима.
- Не комитујте `.env` фајлове или фајлове са извршеним нотебуцима.
- Оставите `.env.example` само као празан узорак.

## Верификација

Покрените скрипту за верификацију репозиторијума:

```powershell
python scripts\verify_notebooks.py
```

Покрените потпуно локално безбедно извршавање нотебука пре објављивања измена имплементације:

```powershell
python scripts\verify_notebooks.py --execute
```

Очекују се следеће провере:

- пролазе локални Markdown линкови
- пролази валидација нотебука у JSON формату
- нотебуци не садрже сачуване излазе или бројач извршења
- пролази скенирање високоризичних шаблона тајни
- јавни нотебуци се успешно извршавају локално
- материјал у нацрту у `drafts/` је намерно прескочен

## Преглед

- Потврдите да README линкови чланака воде ка предвиђеним фајловима.
- Потврдите да сваки чланак има навигацију по репозиторијуму и релевантне линкове до нотебука.
- Потврдите да нацрти нису линковани из јавних индекса осим ако нису спремни за објаву.
- Потврдите да GitHub шаблони за issue и pull request и даље одговарају току рада у репозиторијуму.
- Потврдите да резултати верификације у чланку одговарају најновијем излазу из нотебука.
- Потврдите да је GitHub Actions радни ток очекиван након пуша.
- Потврдите да `CHANGELOG.md` одражава ажурирање које се објављује.
- Потврдите да `CONTRIBUTING.md` и даље одговара току рада у репозиторијуму.

## Git

- Прегледајте `git status --short --branch`.
- Прегледајте `git diff --stat`.
- Комитујте и пушујте само када сте експлицитно спремни.
