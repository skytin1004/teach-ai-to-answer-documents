# 게시 체크리스트

이 체크리스트는 공개 업데이트를 커밋하거나 푸시하기 전에 사용하세요.

## 안전

- API 키, 토큰, 비밀번호 또는 비공개 엔드포인트가 Markdown 파일, 노트북, 샘플 데이터 또는 스크립트에 작성되지 않았는지 확인하세요.
- 자격 증명은 커밋된 파일이 아닌 환경 변수나 관리형 ID에 보관하세요.
- `.env` 파일이나 실행된 노트북 출력 파일은 커밋하지 마세요.
- `.env.example`는 플레이스홀더만 포함하도록 유지하세요.

## 검증

저장소 검증 스크립트를 실행하세요:

```powershell
python scripts\verify_notebooks.py
```

구현 변경 사항을 게시하기 전에 전체 로컬 안전 노트북 실행을 실행하세요:

```powershell
python scripts\verify_notebooks.py --execute
```

예상되는 검사 항목:

- 로컬 Markdown 링크 통과
- 노트북 JSON 검증 통과
- 노트북에 저장된 출력 또는 실행 횟수 없음
- 고위험 비밀 패턴 스캔 통과
- 공개 노트북이 로컬에서 실행됨
- `drafts/` 아래의 초안 자료는 의도적으로 건너뜀

## 검토

- README 문서 링크가 의도된 파일을 가리키는지 확인하세요.
- 각 문서에 저장소 탐색 및 관련 노트북 링크가 있는지 확인하세요.
- 초안이 게시 준비가 되지 않은 한 공개 인덱스에서 링크되지 않았는지 확인하세요.
- GitHub 이슈 및 풀 리퀘스트 템플릿이 여전히 저장소 워크플로우와 일치하는지 확인하세요.
- 문서 내 검증 결과가 최신 노트북 출력과 일치하는지 확인하세요.
- 푸시 후 GitHub Actions 워크플로우가 예상대로 실행되는지 확인하세요.
- `CHANGELOG.md`가 게시하는 업데이트를 반영하는지 확인하세요.
- `CONTRIBUTING.md`가 여전히 저장소 워크플로우와 일치하는지 확인하세요.

## Git

- `git status --short --branch`를 검토하세요.
- `git diff --stat`를 검토하세요.
- 명확히 준비되었을 때만 커밋하고 푸시하세요.
