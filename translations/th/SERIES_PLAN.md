# สอน AI ให้ตอบคำถามจากเอกสารของคุณ - แผนซีรีส์

แผนนี้ติดตามการปล่อยซีรีส์ 1 และซีรีส์ 2 ที่เปิดเผยต่อสาธารณะ งานในส่วน Azure และการประเมินผลจะถูกเก็บเป็นร่างจนกว่าจะมีตัวอย่างที่สมบูรณ์และได้รับการตรวจสอบครบถ้วน

อย่าทำการคอมมิตหรือพุชการเปลี่ยนแปลงจนกว่าจะได้รับคำแนะนำอย่างชัดเจน

## ขอบเขตสาธารณะ

การปล่อยสาธารณะในปัจจุบัน:

- บทความซีรีส์ 1: การตัดสินใจสถาปัตยกรรม RAG, การแลกเปรียบ Azure กับโอเพนซอร์ส, และตำแหน่งที่เหมาะสมของการปรับแต่ง
- บทความซีรีส์ 2: บทเรียน RAG โอเพนซอร์สแบบท้องถิ่น
- โน้ตบุ๊คซีรีส์ 2: ห้องปฏิบัติการ RAG ท้องถิ่นที่รันได้พร้อม FastEmbed, Qdrant, Ollama และ Phi-4-mini
- ข้อมูลตัวอย่าง: ไฟล์ Markdown นโยบายโรงเรียนและแนวทาง AI ของหลักสูตร

ร่างที่ยังไม่อยู่ในดัชนีสาธารณะ:

- การก่อสร้างใหม่ Azure AI Search และ Azure OpenAI
- การประเมินและตรวจสอบการถดถอยของ RAG

## สถานการณ์การสอน

สถานการณ์ที่ใช้ร่วมกันคือผู้ช่วยด้านนโยบายโรงเรียน

ผู้ช่วยจะตอบคำถามนี้จากเอกสารท้องถิ่น:

```text
Can I use generative AI for my final assignment?
```
  
พฤติกรรมที่คาดหวังคือ:

1. โหลดเอกสาร Markdown ท้องถิ่น
2. แยกและแบ่งเป็นส่วนตามหัวข้อ
3. สร้างเอนเบดดิ้งท้องถิ่นและจัดเก็บการแทนค่าเพื่อค้นหาพร้อมกับเมตาดาต้า
4. ดึงส่วนของนโยบายที่เกี่ยวข้อง
5. จัดอันดับใหม่เมื่อจำเป็น
6. สร้างหรือประมวลคำตอบอย่างมีพื้นฐาน
7. ส่งคืนการอ้างอิง
8. บันทึกผลการตรวจสอบ

## การตรวจสอบซีรีส์ 2

ตรวจสอบบน Windows ด้วย Python 3.12.6

- ติดตั้ง `requirements/open-source-rag.txt` สำเร็จ
- รัน `notebooks/series-2-open-source-rag.ipynb` ด้วย `nbclient`
- การตรวจสอบท้องถิ่นผ่าน: โหลดเอกสารตัวอย่าง 2 ฉบับ, สร้าง 8 ชิ้นส่วน, FastEmbed สร้างเอนเบดดิ้งท้องถิ่น 384 มิติ, เริ่มการเก็บข้อมูล Qdrant ในหน่วยความจำ, และแทรกเวกเตอร์ 8 ตัว
- คำถามทดสอบ: "ฉันสามารถใช้ AI สร้างสรรค์สำหรับงานสุดท้ายของฉันได้ไหม?"
- แหล่งข้อมูลที่ดึงมาอันดับต้นหลังจากจัดอันดับใหม่แบบเบา: `school_ai_policy.md`
- ส่วนที่ดึงมาอันดับต้นหลังจากจัดอันดับใหม่แบบเบา: `Final Assignments`
- เส้นทางคำตอบเริ่มต้น: ผู้แต่งคำตอบโปร่งใสท้องถิ่น
- ติดตั้ง Ollama ผ่าน winget; ดึง `phi4-mini:3.8b` สำเร็จ
- เส้นทางการสร้างคำตอบ Ollama: เสร็จสมบูรณ์ด้วย `phi4-mini:3.8b`
- ขนาดไฟล์โมเดล Ollama: ประมาณ 2.49GB บนดิสก์
- ขนาดโมเดล Ollama ที่โหลด: 3.3GB รายงานโดย `ollama ps`
- การใช้ GPU: รายงาน 100% GPU โดย `ollama ps` บน RTX 3060 Laptop GPU
- หน่วยความจำ GPU ที่สังเกตหลังการสร้าง: ประมาณ 3.5GB จาก 6GB
- การรันโน้ตบุ๊คที่ใช้โมเดล FastEmbed แคชและเปิดใช้งานการสร้าง Ollama ผ่านสคริปต์ตรวจสอบสำเร็จในประมาณ 34 วินาที
- สังเกต: การโหลดเอกสารรอบแรกโดยบังเอิญรวมไฟล์ `sample_data/README.md`; โน้ตบุ๊คตอนนี้โหลดเฉพาะเอกสารตัวอย่างที่ตั้งใจไว้สองฉบับโดยชัดเจน

## การตรวจสอบที่เก็บ

- `scripts/verify_notebooks.py` ตรวจสอบลิงก์ Markdown ท้องถิ่น, JSON โน้ตบุ๊ค, ความสะอาดของผลลัพธ์โน้ตบุ๊ค และรูปแบบความลับความเสี่ยงสูง
- `scripts/verify_notebooks.py --execute` รันโน้ตบุ๊คสาธารณะจากโฟลเดอร์รูทของที่เก็บ
- วัสดุร่างภายใต้ `drafts/` ถูกข้ามโดยเจตนา

## งานถัดไป

- ก่อสร้างสถานการณ์เดียวกันใหม่ด้วย Azure AI Search และ Azure OpenAI ในซีรีส์ภายหน้า
- เพิ่มการดึงข้อมูลและการประเมินคำตอบเมื่อการใช้งานท้องถิ่นและ Azure ทั้งคู่เสถียรแล้ว
