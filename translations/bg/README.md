# Научете AI да отговаря на въпроси въз основа на вашите документи

![Преглед на документно-закрепена AI RAG система](../../assets/images/readme-hero.svg)

Този хранилище събира серия от блогове от 2026 г. за изграждане на документно-закрепени AI системи с RAG, Azure AI услуги, алтернативи с отворен код и работни потоци, ориентирани към оценка.

## Предистория

През 2023 г. работих върху двойка уроци за обучаване на ChatGPT да отговаря на въпроси от PDF документи, използвайки Azure AI Search и Azure OpenAI. Идеята за "ChatGPT върху вашите данни" все още се чувстваше нова тогава, а целта беше да се покаже практичен работен поток: съхранявайте документи, индексирайте ги, извличайте релевантно съдържание и генерирайте отговори въз основа на това извлечено съдържание.

През 2026 г. екосистемата на RAG е много по-голяма. Azure AI Search поддържа модерни векторни и хибридни модели на извличане, Azure OpenAI е част от по-широката екосистема Microsoft Foundry Models, а инструменти с отворен код като LangGraph, LlamaIndex, Haystack, Qdrant, Milvus, Weaviate, Chroma, Ollama и vLLM са станали практични избори за реални системи.

Затова исках да прегледам отново тази тема. Въпросът вече не е само "Как да изградя RAG?" Сега има много начини да го изградя, а по-важният въпрос е "Коя архитектура трябва да избера за моя случай?"

Тази серия започва от този слой на вземане на решения, след което го превръща в практически уроци. Първият път на изпълнение изгражда локална RAG система с отворен код, която всеки може да стартира с примерни данни, Qdrant, Ollama и Phi-4-mini.

## Локална генерация с Ollama

Тетрадката от Серия 2 по подразбиране е безопасна за локална работа. За да активирате локална генерация с Ollama, копирайте [.env.example](../../.env.example) в `.env` и попълнете стойностите за Серия 2.

За локална генерация с Ollama в Серия 2, разкоментирайте:

```text
SERIES2_OLLAMA_BASE_URL=http://localhost:11434
SERIES2_OLLAMA_MODEL=phi4-mini:3.8b
```

Тетрадката от Серия 2 автоматично зарежда `.env` от корена на хранилището, като използва `python-dotenv`.

> [!IMPORTANT]
> Не качвайте файлове `.env`, API ключове, лични крайни точки или стойности специфични за наематели. Хранилището умишлено запазва тайните извън файлове Markdown и тетрадки.

Файловете с изисквания са документирани в [requirements/README.md](./requirements/README.md).

За валидация на линкове, структура на тетрадките, чистота на изхода от тетрадките и модели на високо рискови тайни:

```powershell
python -m venv .venv-verify
.\.venv-verify\Scripts\activate
python -m pip install -r requirements\all.txt
python scripts\verify_notebooks.py
```

Скриптовете за проверка са документирани в [scripts/README.md](./scripts/README.md).

За изпълнение на всички локално безопасни тетрадки в същата среда:

```powershell
python scripts\verify_notebooks.py --execute
```

Същият процес на проверка се изпълнява в GitHub Actions при push, pull request-и и ръчно стартиране на работните потоци. Черновите на статии и тетрадки са умишлено изключени от публичния път за проверка.

Преди публикуване на обновления използвайте [PUBLISHING_CHECKLIST.md](./PUBLISHING_CHECKLIST.md).

Вижте [CHANGELOG.md](./CHANGELOG.md) за текущото непубликувано резюме на промените.
