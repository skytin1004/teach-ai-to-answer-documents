# Контролен списък за публикуване

Използвайте този контролен списък преди да извършите commit или push на публични актуализации.

## Безопасност

- Потвърдете, че няма API ключове, токени, пароли или частни крайни точки, записани в Markdown файлове, тетрадки, примерни данни или скриптове.
- Дръжте идентификационните данни в променливи на средата или управлявана идентичност, а не в commit-нати файлове.
- Не commit-вайте `.env` файлове или файлове с изхода от изпълнение на тетрадки.
- Поддържайте `.env.example` само с заместители.

## Проверка

Стартирайте скрипта за проверка на хранилището:

```powershell
python scripts\verify_notebooks.py
```

Изпълнете пълното локално безопасно изпълнение на тетрадки преди публикуване на промени в имплементацията:

```powershell
python scripts\verify_notebooks.py --execute
```

Очаквани проверки:

- локалните Markdown линкове преминават
- валидация на JSON на тетрадките преминава
- тетрадките не съдържат запазени изходи или броячи на изпълнение
- сканиране за високорискови шаблони на тайни преминава
- публичните тетрадки се изпълняват локално
- чернови материал под `drafts/` е умишлено пропуснат

## Преглед

- Потвърдете, че линковете в README статията сочат към предназначените файлове.
- Потвърдете, че всяка статия има навигация към хранилището и свързани линкове към тетрадки.
- Потвърдете, че черновите не са свързани в публичните индекси, освен ако не са готови за публикуване.
- Потвърдете, че шаблоните за GitHub issue и pull request все още съответстват на работния процес на хранилището.
- Потвърдете, че резултатите от проверката в статията съответстват на последния изход от тетрадката.
- Потвърдете, че workflow на GitHub Actions се очаква да се изпълни след push.
- Потвърдете, че `CHANGELOG.md` отразява актуализацията, която се публикува.
- Потвърдете, че `CONTRIBUTING.md` все още съответства на работния процес на хранилището.

## Git

- Прегледайте `git status --short --branch`.
- Прегледайте `git diff --stat`.
- Commit-вайте и push-вайте само когато сте изрично готови.
