# فهرست بررسی انتشار

قبل از کامیت یا پوش عمومی به‌روزرسانی‌ها از این فهرست استفاده کنید.

## ایمنی

- تایید کنید کلیدهای API، توکن‌ها، رمزهای عبور یا نقاط انتهایی خصوصی در فایل‌های Markdown، نوت‌بوک‌ها، داده‌های نمونه یا اسکریپت‌ها نوشته نشده باشند.
- اعتبارنامه‌ها را در متغیرهای محیطی یا هویت مدیریت‌شده نگه دارید، نه در فایل‌های کامیت‌شده.
- فایل‌های `.env` یا خروجی‌های نوت‌بوک اجراشده را کامیت نکنید.
- فایل `.env.example` را تنها به‌عنوان نمونه نگه دارید.

## تایید

اسکریپت تایید مخزن را اجرا کنید:

```powershell
python scripts\verify_notebooks.py
```

اجرای کامل امن نوت‌بوک محلی قبل از انتشار تغییرات پیاده‌سازی:

```powershell
python scripts\verify_notebooks.py --execute
```

چک‌های مورد انتظار:

- لینک‌های محلی Markdown پاس شوند
- اعتبارسنجی JSON نوت‌بوک‌ها موفق باشد
- نوت‌بوک‌ها خروجی ذخیره‌شده یا شمارش اجرای ذخیره‌شده نداشته باشند
- اسکن الگوی اسرار پرخطر موفق باشد
- نوت‌بوک‌های عمومی به‌صورت محلی اجرا شوند
- محتوای پیش‌نویس در پوشه `drafts/` عمدی نادیده گرفته شود

## بازبینی

- تایید کنید لینک‌های مقالات README به فایل‌های موردنظر اشاره دارند.
- تایید کنید هر مقاله دارای ناوبری مخزن و لینک نوت‌بوک‌های مرتبط است.
- تایید کنید پیش‌نویس‌ها از ایندکس‌های عمومی لینک نشده‌اند مگر اینکه آماده انتشار باشند.
- تایید کنید قالب‌های مسائل و درخواست‌های دریافت GitHub هنوز با workflow مخزن همخوانی دارند.
- تایید کنید نتایج تایید در مقاله با آخرین خروجی نوت‌بوک مطابقت دارد.
- تایید کنید workflow اکشن‌های GitHub پس از پوش اجرا خواهد شد.
- تایید کنید فایل `CHANGELOG.md` به‌روزرسانی منتشرشده را بازتاب می‌دهد.
- تایید کنید فایل `CONTRIBUTING.md` هنوز با workflow مخزن مطابقت دارد.

## گیت

- وضعیت `git status --short --branch` را بررسی کنید.
- اختلافات آماری `git diff --stat` را بررسی کنید.
- فقط وقتی کاملاً آماده بودید، کامیت و پوش کنید.
