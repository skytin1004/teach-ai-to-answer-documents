# သင့်စာရွက်စာတမ်းများအပေါ်အခြေခံ၍ AI ကိုမေးခွန်းများကိုဖြေဆိုရန်သင်ကြားခြင်း - စီးရီးအစီစဉ်

ဤအစီအစဉ်သည် ပြည်သူ့စီးရီး 1 နှင့် စီးရီး 2 ထုတ်ပြန်မှုများအားလိုက်နာသည်။ နောက်ပိုင်း Azure နှင့် သုံးသပ်ခြင်းအလုပ်များကို ဥပမာများနဲ့ ပြည့်စုံပြီး စစ်ဆေးပြီးမှသာ မူကြမ်းအနေဖြင့် ထိန်းသိမ်းထားသည်။

ရှင်းလင်းထားမှသာ ပြင်ဆင်မှုများ မလုပ်မိရ။

## ပြည်သူ့ ကန့်သတ်ချက်

ယနေ့အထိ ပြည်သူ့ထုတ်ပြန်မှုများ-

- စီးရီး 1 ဆောင်းပါး - RAG ဖွဲ့စည်းပုံ ဆုံးဖြတ်ချက်များ၊ Azure နှင့် အဖွင့်အလင်းရင်းမြစ် ချိန်နှိုင်းချက်များ၊ နှင့် fine-tuning ၏နေရာ။
- စီးရီး 2 ဆောင်းပါး - ဒေသခံ အဖွင့်အလင်းရင်းမြစ် RAG သင်ခန်းစာ။
- စီးရီး 2 notebook - FastEmbed, Qdrant, Ollama နှင့် Phi-4-mini နှင့်အတူ ဒေသခံ RAG အလုပ်ရုံစမ်း။
- စမ်းသပ် ဒေတာ - ကျောင်းမူဝါဒ နှင့် သင်တန်း AI လမ်းညွှန်ရေး Markdown ဖိုင်များ။

ယနေ့အထိ မူကြမ်းဖြစ်ပြီး ပြည်သူ့ညွှန်ကြားရေးတွင် မပါဝင်သေးသော -

- Azure AI Search နှင့် Azure OpenAI ပြန်လည်တည်ဆောက်ခြင်း။
- RAG သုံးသပ်ခြင်းနှင့် ပြန်လည်စစ်ဆေးခြင်းများ။

## သင်ခန်းစာ သရုပ်ပြ

မျှဝေထားသောသရုပ်ပြမှာ ကျောင်းမူဝါဒ အကူအညီပေးဖြစ်သည်။

အကူအညီပေးသည် ဒေသခံစာရွက်စာတမ်းများမှ ဤမေးခွန်းကိုဖြေသည်-

```text
Can I use generative AI for my final assignment?
```

မျှော်မှန်းထားသော လုပ်ဆောင်ချက်မှာ-

1. ဒေသခံ Markdown စာရွက်စာတမ်းများကို ဖတ်ယူပါ။
2. ခေါင်းစဉ်များအလိုက် ခွဲခြမ်းဝေစုပါ။
3. ဒေသခံ embeddings များ ဖန်တီး၍ metadata နှင့်အတူ ရှာဖွေရေးဖော်ပြချက်များအား သိုလှောင်ပါ။
4. သက်ဆိုင်ရာ မူဝါဒ အပိုင်းကို ရယူပါ။
5. လိုအပ်ပါက ထပ်မံ အဆင့်သတ်မှတ်ပါ။
6. အခြေခံထားသော ဖြေကြားချက်ထုတ်လုပ် သို့မဟုတ် ဖွဲ့စည်းပါ။
7. ကိုးကားချက်များ ပြန်ပေးပါ။
8. စစ်ဆေးမှုရလဒ်များ မှတ်တမ်းတင်ပါ။

## စီးရီး 2 အတည်ပြုခြင်း

Windows ပေါ်တွင် Python 3.12.6 ဖြင့် အတည်ပြုပြီးဖြစ်သည်။

- `requirements/open-source-rag.txt` ကို အောင်မြင်စွာ တပ်ဆင်ပြီး။
- `notebooks/series-2-open-source-rag.ipynb` ကို `nbclient` ဖြင့် အငြင်းပွားစရာမရှိစွာ အကောင်အထည်ဖော်ပြီး။
- ဒေသခံစစ်ဆေးချက် ကောင်းမွန် စီးရီးဖြင့်- စမ်းသပ်စာရွက်စာတမ်း ၂ ခု ဖတ်ရှုပြီး၊ ၈ ခြေလှမ်း ခွဲခြမ်း၊ FastEmbed သည် ၃၈၄ အရွယ် embedded တွေ local ဖန်တီးပြီး၊ Qdrant ကို မှတ်ဉာဏ်အတွင်း စုစည်းမှုကို စတင်ပြီး၊ နှင့် ၈ vectors ထည့်သွင်းပြီး။
- စမ်းသပ်မေးခွန်း - "ကျွန်တော့်နောက်ခံအပ်မဲ့ အစီအစဉ်အတွက် generative AI ကိုအသုံးပြုလို့ရမလား?"
- အလင်းချိုင့်မှု အပြီး ရရှိသော ထိပ်တန်း မူရင်း- `school_ai_policy.md` ဖြစ်သည်။
- အလင်းချိုင့်မှု အပြီး ရရှိသော ထိပ်တန်း တိုက်ရိုက်ပိုင်း - `Final Assignments` ဖြစ်သည်။
- ပုံမှန် ဖြေဆိုချက်လမ်းကြောင်း - ဒေသခံ ထည့်သွင်းသိသာသော ဖြေဆိုချက် ဖန်တီးသူ။
- Ollama ကို winget ဖြင့် တပ်ဆင်ပြီး `phi4-mini:3.8b` ကို အောင်မြင်စွာ ရယူပြီး။
- Ollama ဖြေဆိုမှု လမ်းကြောင်း - `phi4-mini:3.8b` ဖြင့် ပြီးစီး။
- Ollama မော်ဒယ်ဖိုင် အရွယ်အစား - ဒစ်စ့်ပေါ်မှာ ၂.၄၉GB ခန့်။
- Ollama ဖွင့်ထားမော်ဒယ် အရွယ်အစား - `ollama ps` မှ ၃.၃GB ဆီ။
- GPU အပေါ်စွမ်းဆောင်ရည်ချမှု - RTX 3060 Laptop GPU တွင် `ollama ps` က ၁၀၀% GPU ဖြစ်ကြောင်း ပြသည်။
- GPU မှတ်ဉာဏ် အသုံးပြုပုံ - ဖြစ်ထွန်းပြီးနောက် ၆GB မှ ၃.၅GB ခန့်။
- Cached FastEmbed မော်ဒယ်နှင့် Ollama ဖန်တီးမှုပါ notebook အကောင်အထည်ဖော်ရာတွင် verification script ဖြင့် ၃၄ စက္ကန့်ခန့်အတွင်း ဖြတ်သန်းပြီး။
- တွေ့ရှိချက် - စာရွက်စာတမ်းဖတ်မှုအစောပိုင်းတွင် အမှားဖြင့် `sample_data/README.md` ပါဝင်ခဲ့သည်။ ယခု notebook တွင် သတ်မှတ်ထားသော စမ်းသပ်စာရွက်စာတမ်း ၂ ခုသာ ဖတ်ယူသည်။

## repository စစ်ဆေးမှု

- `scripts/verify_notebooks.py` သည် ဒေသခံ Markdown လင့်များ၊ notebook JSON, notebook output သန့်ရှင်းမှု၊ နှင့် မြင့်မားသောအန္တရာယ်ရှိသော လျှို့ဝှက်pattern များကို စစ်ဆေးသည်။
- `scripts/verify_notebooks.py --execute` သည် ပြည်သူ့ notebooks များကို repository ရဲ့ အခြေခံ မှ စမ်းသပ် လည်ပတ်စေသည်။
- `drafts/` အောက်ရှိ မူကြမ်း အရာများကို ရည်ရွယ်ချက်ဖြင့် ကျောပြီး ထားသည်။

## နောက်ဆုံးအလုပ်များ

- အနာဂတ် စီးရီးအစိတ်အပိုင်း အဖြစ် Azure AI Search နှင့် Azure OpenAI ဖြင့် ထိုသရုပ်ပြကို ပြန်လည်တည်ဆောက်ခြင်း။
- ဒေသခံနှင့် Azure ပလက်ဖောင်း နှစ်ခုလုံး တည်ငြိမ်လာမှပြီးရုံနဲ့ ရှာဖွေရေး နှင့် ဖြေကြားချက် သုံးသပ်ခြင်းကို ထည့်သွင်းခြင်း။
