# ပို့စ်လုပ်ရန် စစ်ဆေးရန်စာရင်း

ပြည်သူ့အပ်ဒိတ်များကို commit သို့မဟုတ် push မပြုလုပ်ခင် ဒီစစ်ဆေးရန်စာရင်းကို အသုံးပြုပါ။

## လုံခြုံရေး

- API key, token, password များ သို့မဟုတ် မိမိပိုင် endpoint များကို Markdown ဖိုင်များ၊ notebook များ၊ နမူနာဒေတာများ သို့မဟုတ် script များအတွင်း မရေးသားထားကြောင်းအတည်ပြုပါ။
- အထောက်အထားများကို environment variable များသို့မဟုတ် managed identity တွင်သာ ထိန်းသိမ်းပါ၊ commit လုပ်ထားသောဖိုင်များတွင် မထည့်ပါနှင့်။
- `.env` ဖိုင်များ သို့မဟုတ် အလုပ်လုပ်ပြီးသော notebook output ဖိုင်များကို commit မပြုလုပ်ပါနှင့်။
- `.env.example` ကို placeholder အဖြစ်သာ ထားပါ။

## အတည်ပြုခြင်း

repository verification script ကို Run ပါ -

```powershell
python scripts\verify_notebooks.py
```

publish implementation ပြောင်းလဲမှုများမပြုလုပ်ခင် ပြည်တွင်းလုံခြုံ notebook ကို လုံးဝ run ပြုလုပ်ပါ -

```powershell
python scripts\verify_notebooks.py --execute
```

မျှော်လင့်ထားသော စစ်ဆေးချက်များ -

- ဒေသိယ Markdown ဆက်သွယ်မှုများ မွန်ကန်ပါ
- notebook JSON အတည်ပြုမှု ပြီးမြောက်ပါ
- notebooks များတွင် သိမ်းဆည်းထားသော output များ သို့မဟုတ် အကောင်အထည်ဖော်မှု အရေအတွက် မပါရှိပါ
- အန္တရာယ်မြင့်လျှိုလျှော့သုံး secret pattern စစ်ဆေးမှု ဖြတ်သန်းပါ
- ပြည်သူ့ notebooks များ ဒေသိယအတိုင်း run လုပ်နိုင်ပါ
- `drafts/` အောက်ရှိ မူကြမ်းများကို ရည်ရွယ်ချက်အားဖြင့် မထည့်ပါ

## ပြန်လည်သုံးသပ်ခြင်း

- README ဆောင်းပါးလင့်တွေ မှန်ကန်သောဖိုင်များ ဆီသို့ညွှန်ပြထားကြောင်း အတည်ပြုပါ။
- ဆောင်းပါးတိုင်းတွင် repository navigation နှင့် သက်ဆိုင် notebook link များ ပါဝင်ကြောင်း အတည်ပြုပါ။
- မူကြမ်းများကို ပြည်သူ့ အညွှန်းများမှဆက်သွယ်ထားခြင်း မရှိဘူး၊ ထုတ်ပြန်ရန် အဆင်သင့်ရှိလျှင်သာ ပါရှိပါ။
- GitHub issue နှင့် pull request templates များ repository workflow နှင့် ကိုက်ညီမှုရှိကြောင်း အတည်ပြုပါ။
- ဆောင်းပါးတွင် verification ရလဒ်သည် နောက်ဆုံး notebook output နှင့် ကိုက်ညီကြောင်း အတည်ပြုပါ။
- Push ပြုလုပ်ပြီးနောက် GitHub Actions workflow ပြေးရန် မျှော်မှန်းထားသည်ကို အတည်ပြုပါ။
- `CHANGELOG.md` တွင် ထုတ်ပြန်မည့် အပ်ဒိတ်ကို ဖော်ပြထားကြောင်း အတည်ပြုပါ။
- `CONTRIBUTING.md` သည် repository workflow နှင့် ကိုက်ညီနေဆဲဖြစ်ကြောင်း အတည်ပြုပါ။

## Git

- `git status --short --branch` ကို ပြန်လည်စစ်ဆေးပါ။
- `git diff --stat` ကို ပြန်လည်စစ်ဆေးပါ။
- ရှင်းလင်းစွာ တိုင်ကြားတဲ့အခါမှသာ commit နှင့် push ပြုလုပ်ပါ။
