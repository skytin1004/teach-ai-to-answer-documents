# Контрольный список публикации

Используйте этот контрольный список перед подтверждением или отправкой публичных обновлений.

## Безопасность

- Подтвердите, что в файлах Markdown, ноутбуках, образцах данных или скриптах не записаны API-ключи, токены, пароли или приватные конечные точки.
- Храните учетные данные в переменных окружения или управляемой идентичности, а не в зафиксированных файлах.
- Не фиксируйте файлы `.env` или файлы вывода выполненных ноутбуков.
- Храните `.env.example` только как заполнители.

## Проверка

Запустите скрипт проверки репозитория:

```powershell
python scripts\verify_notebooks.py
```

Запустите полное локальное безопасное выполнение ноутбуков перед публикацией изменений в реализации:

```powershell
python scripts\verify_notebooks.py --execute
```

Ожидаемые проверки:

- локальные ссылки Markdown проходят проверку
- проходит проверка валидации JSON ноутбуков
- ноутбуки не содержат сохранённых выводов или счетчиков выполнения
- проходит сканирование на шаблоны высокорискованных секретов
- публичные ноутбуки выполняются локально
- черновики в `drafts/` намеренно пропускаются

## Обзор

- Подтвердите, что ссылки в README ссылаются на нужные файлы.
- Подтвердите, что в каждой статье есть навигация по репозиторию и ссылки на связанные ноутбуки.
- Подтвердите, что черновики не связаны из публичных индексов, если они не готовы к публикации.
- Подтвердите, что шаблоны проблем (issues) и запросов на изменение (pull request) на GitHub все еще соответствуют рабочему процессу репозитория.
- Подтвердите, что результаты проверки в статье соответствуют последнему выводу ноутбука.
- Подтвердите, что рабочий процесс GitHub Actions должен запускаться после отправки.
- Подтвердите, что файл `CHANGELOG.md` отражает публикуемое обновление.
- Подтвердите, что `CONTRIBUTING.md` по-прежнему соответствует рабочему процессу репозитория.

## Git

- Просмотрите `git status --short --branch`.
- Просмотрите `git diff --stat`.
- Фиксируйте и отправляйте изменения только при полной готовности.
