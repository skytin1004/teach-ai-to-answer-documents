# قائمة التحقق من النشر

استخدم هذه القائمة قبل الالتزام أو دفع التحديثات العامة.

## السلامة

- تأكد من عدم كتابة مفاتيح API، الرموز، كلمات المرور، أو نقاط النهاية الخاصة في ملفات Markdown، دفاتر الملاحظات، بيانات العينة، أو البرامج النصية.
- احتفظ بمعلومات الاعتماد في متغيرات البيئة أو الهوية المُدارة، وليس في الملفات التي تم الالتزام بها.
- لا تقم بالالتزام بملفات `.env` أو ملفات إخراج دفاتر الملاحظات المنفذة.
- احتفظ بملفات `.env.example` كعينة فقط.

## التحقق

شغّل برنامج التحقق من المستودع:

```powershell
python scripts\verify_notebooks.py
```

شغّل التنفيذ الكامل الآمن محليًا لدفتر الملاحظات قبل نشر تغييرات التنفيذ:

```powershell
python scripts\verify_notebooks.py --execute
```

الفحوصات المتوقعة:

- تمرر الروابط المحلية في Markdown
- يمر التحقق من صحة JSON لدفاتر الملاحظات
- لا تحتوي دفاتر الملاحظات على إخراجات محفوظة أو عدادات تنفيذ
- يمر فحص نمط الأسرار عالية الخطورة
- يتم تنفيذ دفاتر الملاحظات العامة محليًا
- المواد المسودة تحت `drafts/` يتم تخطيها عمدًا

## المراجعة

- تأكد من أن روابط مقالات README تشير إلى الملفات المقصودة.
- تأكد من أن كل مقالة تحتوي على تنقل في المستودع وروابط لدفاتر الملاحظات ذات الصلة.
- تأكد من أن المسودات غير مرتبطة بالمفهرسات العامة إلا إذا كانت جاهزة للنشر.
- تأكد من أن نماذج قضايا GitHub وطلبات السحب لا تزال تتطابق مع سير عمل المستودع.
- تأكد من أن نتائج التحقق في المقالة تتطابق مع آخر إخراج لدفتر الملاحظات.
- تأكد من أن سير عمل GitHub Actions من المتوقع تشغيله بعد الدفع.
- تأكد من أن `CHANGELOG.md` يعكس التحديث الجاري نشره.
- تأكد من أن `CONTRIBUTING.md` لا تزال تتطابق مع سير عمل المستودع.

## Git

- راجع `git status --short --branch`.
- راجع `git diff --stat`.
- قم بالالتزام والدفع فقط عندما تكون جاهزًا صراحةً.
