# Навчіть ШІ відповідати на запитання на основі ваших документів

![Огляд системи ШІ на основі документів RAG](../../assets/images/readme-hero.svg)

Цей репозиторій містить серію блогів 2026 року про створення систем ШІ на основі документів із RAG, сервісами Azure AI, відкритими альтернативами та робочими процесами, орієнтованими на оцінювання.

## Передумови

У 2023 році я працював над парою навчальних посібників про те, як навчити ChatGPT відповідати на запитання з PDF-документів за допомогою Azure AI Search та Azure OpenAI. Ідея «ChatGPT на ваших даних» тоді ще здавалась новою, і метою було показати практичний робочий процес: зберігати документи, індексувати їх, отримувати релевантний контент і генерувати відповіді на основі отриманого контексту.

У 2026 році екосистема RAG значно розширилася. Azure AI Search підтримує сучасні вектори та гібридні моделі пошуку, Azure OpenAI є частиною ширшої екосистеми Microsoft Foundry Models, а відкриті інструменти, такі як LangGraph, LlamaIndex, Haystack, Qdrant, Milvus, Weaviate, Chroma, Ollama та vLLM, стали практичними варіантами для реальних систем.

Саме тому я хотів знову звернутися до цієї теми. Запитання тепер уже не лише «Як побудувати RAG?» - існує багато способів його створення, і більш важливе питання — «Яку архітектуру обрати для моєї ситуації?»

Ця серія починається з цього рівня прийняття рішень, а потім перетворюється на практичні навчальні посібники. Перший шлях реалізації будує локальну відкриту систему RAG, яку можуть запустити всі з прикладними даними, Qdrant, Ollama та Phi-4-mini.

## Локальна генерація Ollama

Зошит Серії 2 за замовчуванням безпечний для локального запуску. Щоб увімкнути локальну генерацію Ollama, скопіюйте файл [.env.example](../../.env.example) у `.env` і заповніть значення Серії 2.

Для генерації Ollama Серії 2 розкоментуйте:

```text
SERIES2_OLLAMA_BASE_URL=http://localhost:11434
SERIES2_OLLAMA_MODEL=phi4-mini:3.8b
```

Зошит Серії 2 автоматично завантажує `.env` з кореня репозиторію завдяки `python-dotenv`.

> [!IMPORTANT]
> Не комітьте файли `.env`, API-ключі, приватні кінцеві точки або значення, специфічні для орендаря. Репозиторій свідомо тримає секрети поза Markdown файлами та зошитами.

Файли вимог документовані у [requirements/README.md](./requirements/README.md).

Щоб перевірити посилання, структуру зошитів, чистоту вихідних даних та знайти ризикові патерни секретів:

```powershell
python -m venv .venv-verify
.\.venv-verify\Scripts\activate
python -m pip install -r requirements\all.txt
python scripts\verify_notebooks.py
```

Скрипти перевірки документовані у [scripts/README.md](./scripts/README.md).

Щоб виконати усі локально-безпечні зошити в тому самому оточенні:

```powershell
python scripts\verify_notebooks.py --execute
```

Такий самий потік перевірки запускається у GitHub Actions при пушах, запитах на злиття та ручних викликах робочого процесу. Чернетки статей і зошитів навмисно виключені з публічного шляху перевірки.

Перед публікацією оновлень скористайтесь [PUBLISHING_CHECKLIST.md](./PUBLISHING_CHECKLIST.md).

Дивіться [CHANGELOG.md](./CHANGELOG.md) для поточного не опублікованого звіту про зміни.

Правила внеску та гігієни зошитів дивіться у [CONTRIBUTING.md](./CONTRIBUTING.md).
