# اشاعت چیک لسٹ

اس چیک لسٹ کو عوامی اپ ڈیٹس کو کمٹ یا پش کرنے سے پہلے استعمال کریں۔

## حفاظت

- تصدیق کریں کہ کوئی API کلیدیں، ٹوکنز، پاس ورڈز، یا نجی اینڈ پوائنٹس مارک ڈاؤن فائلز، نوٹ بکس، سیمپل ڈیٹا، یا اسکرپٹس میں درج نہ ہوں۔
- اسناد کو ماحول کے متغیرات یا منظم شناخت میں رکھیں، نہ کہ کمٹ کی گئی فائلوں میں۔
- `.env` فائلز یا چلائی گئی نوٹ بک آؤٹ پٹ فائلز کو کمٹ نہ کریں۔
- `.env.example` کو صرف جگہ دار کے طور پر رکھیں۔

## تصدیق

ریپوزیٹری کی تصدیقی سکرپٹ چلائیں:

```powershell
python scripts\verify_notebooks.py
```

اشاعت سے پہلے مکمل لوکل-سیف نوٹ بک کا نفاذ چلائیں:

```powershell
python scripts\verify_notebooks.py --execute
```

متوقع چیکس:

- لوکل مارک ڈاؤن لنکس کامیاب ہوں
- نوٹ بکس کا JSON تصدیق کامیاب ہو
- نوٹ بکس میں محفوظ شدہ آؤٹ پٹس یا نفاذ کی گنتی نہ ہو
- ہائی رسک سیکریٹ پیٹرن اسکین کامیاب ہو
- پبلک نوٹ بکس لوکل طور پر چلیں
- ڈرافٹ مواد `drafts/` کے تحت جان بوجھ کر نظر انداز کیا گیا ہو

## جائزہ

- تصدیق کریں کہ README آرٹیکل کے لنکس مطلوبہ فائلوں کی طرف اشارہ کرتے ہوں۔
- تصدیق کریں کہ ہر آرٹیکل میں ریپوزیٹری نیوی گیشن اور متعلقہ نوٹ بک کے لنکس موجود ہوں۔
- تصدیق کریں کہ ڈرافٹس پبلک انڈیکس سے لنک نہ کیے گئے ہوں جب تک کہ وہ اشاعت کے لیے تیار نہ ہوں۔
- تصدیق کریں کہ GitHub ایشو اور پل ریکویسٹ ٹیمپلیٹس اب بھی ریپوزیٹری کے ورک فلو سے مماثل ہوں۔
- تصدیق کریں کہ آرٹیکل میں تصدیقی نتائج تازہ ترین نوٹ بک کے آؤٹ پٹ سے مطابقت رکھتے ہوں۔
- تصدیق کریں کہ GitHub Actions ورک فلو پش کے بعد چلنے کی توقع ہو۔
- تصدیق کریں کہ `CHANGELOG.md` اپ ڈیٹ کی عکاسی کرتا ہے جو شائع کی جا رہی ہو۔
- تصدیق کریں کہ `CONTRIBUTING.md` اب بھی ریپوزیٹری کے ورک فلو کے مطابق ہو۔

## Git

- `git status --short --branch` کا جائزہ لیں۔
- `git diff --stat` کا جائزہ لیں۔
- صرف جب واضح طور پر تیار ہوں تو کمٹ اور پش کریں۔
